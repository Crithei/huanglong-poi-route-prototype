## 这次要让游客观察什么

整个页面始终是一片四池相连的景观：上游池分往左右两池，再汇入下游池。改变条件后，它接着原来的状态演化。画面位置不重新生成，退水也不抹掉已经积累的池沿。

既有四章3D继续表达一滴水的水流、溶解、出露与沉积旅程。实验室把视角拉到池群，让游客通过反复比较理解：来水怎样逐级传递，暂时少水为何不会同时干涸，什么条件会留下薄层，水色为什么不能直接代表钙华增长。

本页采用原创Canvas景观画面和SVG剖面，侧重连续过程与手机操作；没有把插画视角包装为实测地形或水动力仿真。

## 建议体验顺序

1. 点「开始演化」，观察上游先蓄水，逐渐连通下游。1×、3×、6×只控制演示速度。
2. 点「起点对照」，直接拖动画面的分界线，或用下方滑杆比较同一片池群的前后状态。也可把当前状态设为新的起点。
3. 减少来水，观察各池变化的先后。来水较弱也可能继续蓄水，解释文字依据所选池子的实际收支判断上涨、下降或渐稳。
4. 保持来水，只改变钙供给或逸散条件，继续观察池沿和池底的累积。再改变光照，区分观看效果与沉积条件。
5. 轻点池面或四个池子按钮，展开对应剖面。虚线标记初始池沿；当前水面、池沿与池底来自同一模型。
6. 点「留下这次观察」，保存当前完整状态。观察卡可作为对照，或写进数字手账的新一页，继续编辑与导出。

「推演一段」推进5个演示单位；不播放时可连续使用。「复位」只重置池群与对照起点，保留观察卡、贴纸、打卡和手账。预设只改变相关输入，例如「柔光观察」只改光照。

## 输入和因果

| 输入 | 直接影响 | 不应被理解为 |
|---|---|---|
| 来水量 | 上游池的水和溶解物输入，再通过溢流传到下游 | 实时河流监测、真实流量或现场丰枯水预测 |
| 溶解钙供给 | 新来水携带的可沉积物；不删除池中已有溶解物 | 真实钙浓度、可饮用水指标 |
| CO₂逸散条件 | 在假定适宜水化学条件下，控制部分溶解物析出的趋势 | 完整碳酸盐平衡、可直接换算的气体流量 |
| 光照 | 景观亮度、反光和水色的观看效果 | 光越强就必定长出更多钙华 |

内部数值均为相对量，没有真实物理单位。默认暂停；离开实验标签、离开随行主页面、切到后台或池面滚出视野时暂停，回来不自动播放、不追赶遗漏时间。系统开启减少动态效果时隐藏连续播放，只保留手动步进。窄屏上场景只在条件操作区内吸附，阅读解释或手账卡时会让出空间。

## 收集、手账与存档

- 未到站可完整探索、保存观察、写手账，不发正式发现贴纸。
- 在五彩池、金沙铺地、争艳彩池、迎宾池任一处已有有效到达记录后，记录三类状态：水路连通、水位下降、池沿积累，获得一枚原创「池群观察者」贴纸。
- 一条观察可以同时记录多类新发现；同类不重复计数。仍采用原型手动到达方式，不代表现场定位核验。
- 相同状态重复点击不增加观察卡；不同试验即使时间和当前滑杆相同，只要池群状态不同就分别保存。
- 最多6条快照，超过后滚动替换最早一条，界面提示可提前写进手账。手账最多12页，满时说明原因，不覆盖旧页。
- 「写进手账」加入所选池子、现象、相对条件与演示时刻的文字，并使用已有可用收藏；没有把画面截图自动贴入手账。
- 旧三种发现贴纸、六主章、主题章、既有手账与四章3D进度兼容保留。自然观察主题继续接受旧贴纸和新贴纸。

`huanglong.pool-lab.v1` 保存世界状态、比较基准、观察卡、选中池子和速度；比较开关与分界位置是临时操作。恢复时进行数值范围校验，始终暂停。读写本机存储失败时明示限制。没有账号同步，也没有完整离线缓存。

## 模型与实现说明

`pool-lab-state.js` 为独立纯模型，使用0.05以内的内部步长，单次最多推进5个演示单位。上游按照固定比例向左右两池分流，左右池都流向下游。池面高过池沿时，超高越大，演示中的出流越强；渗漏携带相同比例的溶解物并单独记账。

沉积受已有溶解物、湿润程度和逸散条件限制，不凭空产生钙。溶解物输入、输出、损失、池内余量和累计沉积保持收支闭合。沉积量改变池沿和池底，但形态增长设有演示上限；后续沉积仍记入总量，因此不能把描画出的几何体当作真实沉积体积。

`pool-lab-scene.js` 使用同一套720×700的不规则轮廓绘制当前世界和比较基准。水面范围/水色来自水深，池沿厚度来自累计增长，溢流线与沉积微粒来自对应状态；像素比上限1.5。`pool-lab.js` 管理输入、绘制、暂停、记录与护照桥接。Canvas不可用时仍提供状态说明和SVG剖面。

该模型没有计算完整碳酸盐平衡、温度、生物作用、侵蚀、复杂地下水、天气或真实地形。水文与地貌变化被分别压缩到可见尺度；不能据此推算黄龙钙华形成的年限、现场水深、流量或季节状况。用于游客科普前仍需地学审校与实地可用性验证。
