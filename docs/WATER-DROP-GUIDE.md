# 随行旅行册与 Three.js 微缩黄龙

本轮依据已讨论的“本站攻略 → 地点打卡 → 一滴水故事”制作可操作原型。以移动端竖屏为主，当前站操作放在顶部，3D 体验作为本轮主视觉，下接本站攻略与行程记录。使用 `?view=follow` 可直接进入。

## 模型与操作

- 原创程序化低多边形模型：六层错落彩池、蜿蜒池沿、小池分隔、溢流水片、分面岩体、杉树、花草和木栈道。
- 一个带表情的水滴沿章节改变位置，流水光点沿池群曲线移动；沉积阶段出现晶体与新增池沿，拖动时间滑杆观察厚度变化。
- 水滴故事为“水携带溶解物质 → 跌水与二氧化碳逸出 → 沉积 → 长期积累”。没有把水滴直接变成石头，也未把动画时长换算为真实年限。
- 左右拖动旋转；按钮提供旋转、放大、恢复、暂停。竖向手势保留页面滚动，键盘可操作按钮与原生滑杆。
- 不支持 WebGL 时显示静态彩池示意，文字与时间滑杆仍可用。尊重减少动态效果设置；场景离屏或页面在后台时停止渲染。

模型是解释过程的艺术化微缩景观，**不是五彩池测绘、现场机位、真实流体模拟或沉积速率模型**。镜头和点位不用于导航。

## 独立模型文件

`assets/models/huanglong-water-landscape.glb` 可导入支持 glTF 2.0 的软件，例如 Blender。约 7,056 个三角形、739 KB，使用网格和材质，不依赖外部纹理。它导出完成状态的模型、水滴和沉积物，未包含网页的程序动画；动画逻辑在 `src/water-landscape.mjs` 与 `src/water-scene.mjs`。

模型/印章为本项目原创程序化图形；Three.js 0.180.0 为 MIT，许可证在 `assets/THREE-LICENSE`。这是 Web 原型的 Three.js 场景；微信小程序正式版本还需针对 Canvas/WebGL 环境适配，不能直接宣称原生小程序已可运行。

## 打卡与奖励

“我已到达”产生日期化地点印章，进入正在游览状态；“逛完了”才完成该站并推进游线。印章按 POI ID 去重，增删行程不清除已收集印章。手动记录用于演示，不作真实到场或实物兑换凭证。

游戏奖励与地点奖励分开：完成三步并把时间推至末端才可领取“水的见证者”；重玩不会丢失或重复发章。游戏与地点打卡均不要求对方先完成。

印章册显示已收集和待发现景点，可生成本地 PNG 纪念卡，包含到达景点、日期、水滴体验纪念、原创彩池插画。生成时直接展示图片，并提供下载链接；内嵌浏览器是否允许文件下载取决于容器，可独立打开网页保存。不会上传照片或自动对外分享。

## 现场攻略

五彩池、金沙铺地、盆景池有专项观察任务与构图建议。其余景点复用已整理的 `visitGuide`、`highlights`、`photoTip`，支持“怎么玩/怎么拍”页签。构图图案标明示意，不假装为核实过的实景机位。

## 进度与资源

`follow-state.js` 为可测试纯逻辑，`follow.js` 为 UI。`huanglong.travel-journal.v1` 保存所选景点、偏好、完成站点、当前到达、印章与游戏进度；恢复时校验版本、ID、日期和数值。存储不可用时显示提示，仍可继续本次体验。数据仅在当前浏览器/域名，不跨设备同步；清理浏览器数据会丢失记录。

`src/water-scene.mjs` 延迟到进入随行时才创建 renderer；IntersectionObserver/visibility 控制动画，ResizeObserver 适配尺寸，页面卸载释放资源。设备像素比最高 1.65，不使用后处理。实际低端手机帧率尚未实机测量。

## 开发和构建

```powershell
npm.cmd ci
npm.cmd test
npm.cmd run build:water
npm.cmd run build:cloudflare
npm.cmd run deploy:cloudflare
```

`build:water` 将 Three.js 与场景打包为 `assets/water-scene.js` 并导出 GLB。Cloudflare 构建会自动先重建三维产物，避免源码与浏览器包不一致。网站使用本地 IIFE 包，无运行时 CDN 模块依赖；`file://` 下也可执行脚本，但地图仍需要 HTTP 配置端点。主资源白名单为 18 个文件，研究、测试、源码及凭据不公开。
