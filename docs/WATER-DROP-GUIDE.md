# 随行四章：到站，读懂一滴水

当前版本提供水流、溶解、出露、沉积四个独立低多边形场景。打开 `?view=follow` 进入随行。2026-09-20 形象锚点版让同一滴水贯穿四章：第二章拖动真实建模气团，第四章拖动水滴去下一处，或用按钮带它出发。沿用水位滑杆与逐池生成，没有模型数字徽标。仍为 Web 原型，正式微信小程序需要适配 Canvas/WebGL 和定位权限。

## 怎么体验

1. 随行顶部点击“我已到达”，收下地点印章；“逛完了”才推进下一站。
2. 到达任一关联 POI，解锁对应章节。也可以在锁定章节选择“我此刻在”的景点，再点“我已到达 · 打卡解锁”补记；不会跳过游线其他站。
3. 点击章节卡切换模型。未解锁时可以旋转预览，互动与奖励锁定。四章独立，支持索道上行、徒步上行和逆序到达。
4. 水流：轻点三个实体水槽，或使用下方上游/中游/下游按钮转向。水源持续流动，未接通时沿当前分支流走；正确连通后持续进入地下。观察 4 秒自动收章。
5. 溶解：将画面中的低多边形 CO₂ 气团拖到标着“让水带上 CO₂”的水滴上；松手后气团收拢消散。也有等效点击/键盘按钮。水自动流过岩层，三处石灰岩依次缩小，金色溶解物随水移动；8 秒自动收章，不再需要点观察编号。
6. 出露：只拖动水位滑杆。达到 65% 的演示阈值后，地下渗流连接单一泉口，持续出水并释放 CO₂ 气泡；观察 4 秒自动收章。完成后仍可调水位、观察出流停止或恢复。
7. 沉积：上方三池保留，下方三池初始不显示。把水滴拖到下一片淡光环处，或点击“带水滴去…”按钮，水滴先移动到新区域（约 0.7 秒），随后依次播放池沿生长（3 秒）、蓄水（3 秒）、溢流（2.5 秒）。一轮结束，水滴停在刚完成的彩池，等待你带它去下一处。三轮完成收章，已完成彩池保持溢流。
8. 四章集齐获得“山水同行者”；重玩不会重复发奖。回看水流时也可以继续转向，不清除已经收下的奖励。

旋转山水可左右拖动，手机上下手势保留滚动；也有镜头按钮。气团或水滴未拖中、手势取消时会返回原处。动画进行中，不能再次启动下一池。拖动的是实际 3D 模型；透明触摸区域跟随模型投影，不另外贴一颗移动图标。选择/删除景点、阅读详情与玩游戏不会自动产生地点打卡。

## 地点与科普边界

| 章节 | 任一关联地点 | 模型 |
| --- | --- | --- |
| 水流 | 金沙铺地、迎宾池 | 山坡、持续源水、三段旋转水槽、地表径流与地下汇水 |
| 溶解 | 洗身洞观景台 | 山体岩层剖面、裂隙、水滴、逐渐缩小的石灰岩及溶解物 |
| 出露 | 飞瀑流辉、莲台飞瀑 | 有地表植被的山体及剖面、连续水位面、单一泉口和气泡 |
| 沉积 | 五彩池、争艳彩池、盆景池 | 前三池与三处逐步出现的池沿、蓄水、溢流和沉积粒子 |

地点绑定是科普主题关联。洗身洞观景台不代表开放入洞；地下剖面不是现场测绘。借飞瀑理解出露和跌水，不把它宣称为已经核实的地下水源口。虚拟转向水槽、水位百分比与动画秒数不对应景区设施、实际海拔或真实年限。

含 CO₂ 的水在合适条件下可溶解碳酸盐岩，CO₂ 逸出等变化可促使碳酸钙沉积。出露是地下水来到地表，逸出是气体离开水体；金色粒子表示溶解物，水滴本身不会变成石头。池沿生长、蓄水和溢流在自然中相互交织，这里分阶段表现便于观察。

## 模型与渲染

原创程序化地景，Three.js 0.180.0（MIT），许可证在 `assets/THREE-LICENSE`。四份 GLB 可导入 Blender 等 glTF 2.0 软件，包含完成状态的可见几何与材质；已消散的 CO₂ 气团不出现在完成态 GLB 中。网页交互、气团形象和动态粒子逻辑保留在源码中。

| GLB 文件 | 三角形数（含隐藏对象预算） | 导出大小 |
| --- | ---: | ---: |
| `huanglong-flow.glb` | 5,351 | 287 KiB |
| `huanglong-dissolution.glb` | 4,002 | 249 KiB |
| `huanglong-emergence.glb` | 4,354 | 252 KiB |
| `huanglong-water-landscape.glb` | 11,346 | 607 KiB |

渲染器进入随行才创建，四章共用一个 WebGL 上下文，切章释放旧模型。转向、岩石缩小、水位和水流显隐采用插值过渡，切章有轻微进入过渡。几何在初始化时创建，动画更新复用对象。像素比最高 1.65，单模型测试预算低于 18,000 三角形。

场景离屏、页面后台或用户暂停时，动画与游戏计时一起停止，不追赶离开的时间。完成奖励不终止水流动画。开启系统“减少动态效果”后，连续动画冻结，使用“查看下一状态”查看关键状态；仍需先接通水路、加入 CO₂、提高水位或启动彩池一轮。

不支持 WebGL/上下文丢失时显示对应文字和二维流程，保留等效按钮及自动进度。网页本地包约 545 KiB，无运行时 Three.js CDN 依赖。实际低端手机 GPU 性能尚未实机测量。

## 状态、保存与迁移

- 地点打卡是游客明确的手动到达记录，没有调用 GPS、后台定位、景区二维码或实物兑换；不是验证到场的凭证。
- 存档键仍为 `huanglong.travel-journal.v1`，内部 schema 升级为 version 3。
- v1 升级前保存到同名 `.backup`；v2 升级前保存到 `.v2.backup`，不会覆盖已存在的备份。
- 保留原路线、地点印章、偏好、旧纪念章和已获得的四章奖励。v2 未完成的溶解/沉积需要按新玩法重玩，兼容的水槽方向和水位保留。
- 读取时校验 POI、时间和范围；没有关联到达依据的章节进度丢弃。状态层也检查锁定和合法操作。
- `tickChapter(state,id,seconds)` 只推进已解锁的当前过程，每次最多 0.25 秒。UI 在显示且未暂停时调用，约每秒保存；切章、交互、奖励和隐藏页面也会保存。
- 游戏状态：水流 `channels/runoff`，溶解 `charged/elapsed`，出露 `level/exposure`，沉积 `sequence/fraction/running/travel`。章节共同保留 `won/earnedAt`。
- 形象锚点版为 schema3 增加可选 `travel`（0–1），用于先移动再生长；旧存档缺失时按已到达处理，不打断正在进行的彩池生成。
- 保存仅限当前浏览器/域名，不能跨设备同步。存储不可用时提示；清理数据会丢失记录。

后续景区定位、二维码或设施接口应产生经过验证的到达事件，再进入地点印章/章节解锁流程。游戏代码不应直接授予验证到场记录。

## Git 回退

当前实验分支 `feature/fluid-water-story`。本轮前的连续过程版本保存在标签 `archive/2026-09-20-before-water-anchor`（`f399d78`）；更早四章版本标签为 `archive/2026-09-20-before-fluid-scenes`（`7c289b6`）。更早的单场景标签和稳定 `main` 均保留。

通过独立目录恢复上一版并重新部署：

```powershell
git worktree add ../huanglong-before-anchor archive/2026-09-20-before-water-anchor
Set-Location ../huanglong-before-anchor
npm.cmd ci
npm.cmd run deploy:cloudflare
```

回退到 `before-water-anchor` 仍接受当前 schema3，不需要替换存档，只会忽略新增加的移动阶段。

只有继续回退到 `before-fluid-scenes`（只接受 v1/v2）时，才需要先备份当前记录，再恢复更早的备份（操作会替换当前浏览器记录）：

```js
const key = 'huanglong.travel-journal.v1';
const current = localStorage.getItem(key);
if (current) localStorage.setItem(key + '.v3.before-rollback', current);
const saved = localStorage.getItem(key + '.v2.backup') || localStorage.getItem(key + '.backup');
if (saved) localStorage.setItem(key, saved);
```

如果此设备从新版开始、没有旧备份，先保留 `.v3.before-rollback`，在旧版使用新行程；不要强改存档版本号。
